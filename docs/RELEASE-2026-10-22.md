# Lokale versie en TikTok

De branch `lokale-versie` bevat de lokale app, met Video Studio, Content Planner, alle bestaande migraties en de merge van `claude/tiktok-integration`. De lokale versie vóór de merge is vastgelegd als `be44a59`.

## Publicaties

Plannerposts worden bij expliciet opslaan op de server bewaard, met een aparte levering per kanaal (Instagram, Facebook, TikTok). Oude browserconcepten blijven leesbaar en worden pas na opnieuw opslaan ingepland; er worden geen oude concepten stilzwijgend gepubliceerd. Desktopmedia uploaden direct naar R2; Drive-video's worden met de verbonden account geïmporteerd. Alle opgeslagen tijdstippen bevatten een expliciete tijdzone.

Een atomaire claim voorkomt dubbel versturen door gelijktijdige workers. Succesvolle leveringen worden niet opnieuw verstuurd als een ander kanaal faalt. TikTok-publicatie-ID's worden vóór het uploaden bewaard en de verwerking wordt daarna opgevolgd. Onderbroken, onzekere leveringen vragen controle in plaats van automatisch opnieuw te posten. De status is zichtbaar bij het publicatiemoment.

`/api/cron/publish-content` vereist `Authorization: Bearer <CRON_SECRET>`. De bestaande Mac-pipeline roept dezelfde sociale planner aan via `/api/video-pipeline/publish-due`. De GitHub Actions-workflow kan dit elke vijf minuten doen zonder actieve Mac, nadat hij op de standaardbranch is geactiveerd en `SIMPLY_CONTENT_CRON_SECRET` is ingesteld. GitHub kan geplande runs vertragen; dit is geen garantie op de exacte minuut.

Vercel Hobby ondersteunt geen cron per minuut. De bestaande dagelijkse Vercel-taken blijven behouden. De bestaande Instagram-routine voor Video Studio en carrousels is behouden.

## Configuratie en media

Productie gebruikt `APP_URL=https://simplyapp.be`. `TIKTOK_CLIENT_KEY` en `TIKTOK_CLIENT_SECRET` horen uitsluitend in de hostingomgeving. Redirect URI: `https://simplyapp.be/api/integrations/tiktok/callback`. Verbind daarna de TikTok-testaccount in Content Planner. Voor de sandbox is de standaardzichtbaarheid `SELF_ONLY`; publieke publicaties vereisen TikTok-goedkeuring en een expliciete wijziging van `TIKTOK_PRIVACY_LEVEL`.

Afbeeldingen en lettertypes staan in de bestaande R2-opslag. `src/lib/static-assets.json` bevat publieke URL's; Next.js serveert die als fallback op de oorspronkelijke paden. `scripts/sync-static-assets.ts` kan gewijzigde lokale assets publiceren zonder ze in Git op te nemen.

`.env*`, credentials, media, dependency-mappen, lokale tooling en builds zijn uitgesloten van Git. Eerder gevolgde media blijven lokaal behouden maar zijn uit de branch verwijderd. Bestaande Git-geschiedenis is niet herschreven.

## Validatie

- `npm run test:scheduling`: gelijktijdige claims, onafhankelijke kanalen, geen dubbele retries, TikTok-statuspolling, herstel na timeouts, inputvalidatie en tijdzonevereisten.
- `npm run build`: productiebuild vanuit een aparte releasekopie met een gewone `node_modules`-map; geen invloed op de lokale dev-cache.
- `vercel-build` voert ontbrekende Prisma-migraties uit vóór de productiebuild; er wordt geen database-reset of `db push` gebruikt.
